Sprint11（HITL：审批/暂停/恢复/审计）已落地完成，并已把 HITL 挂到 MCP 工具调用链路上：当某个 MCP server/tool 被标记为需要审批时，调用会返回 `hitl_pending`，随后可通过 HITL 接口进行 approve/reject/edit，再 `resume` 执行；同时写入审计表与 context events。全量测试通过：`22 passed`。

**核心能力**
- 审批状态机：`pending / approved / rejected / edited`，并支持 `resume`（执行被挂起的工具调用）
- MCP 工具调用拦截：需要审批时返回 `409`，并创建 `hitl_requests` 记录
- 审计落库：`audit_logs` 记录 HITL 的 created/approve/reject/edit 行为
- 与 AgentRun 的“暂停”对齐：Agent 运行中遇到 `hitl_pending` 会把 run 标记为 `paused`（并记录 `waiting_hitl_request_id`），用于后续扩展“真正的继续执行”

**API（/api/v1 同样可用）**
- 列表：`GET /hitl/requests?status_filter=pending`
- 详情：`GET /hitl/requests/{hitl_request_id}`
- 审批：`POST /hitl/requests/{hitl_request_id}/approve`
- 拒绝：`POST /hitl/requests/{hitl_request_id}/reject`
- 编辑参数：`POST /hitl/requests/{hitl_request_id}/edit`
- 恢复执行：`POST /hitl/requests/{hitl_request_id}/resume`

**如何触发一次 HITL（最小演示）**
- 注册 MCP server 时在 `config` 里加：`"requires_approval": true`
- 调用 tool 时会返回：
  - HTTP `409`
  - `detail = {"error":"hitl_pending","hitl_request_id": <id>}`
- 然后走：
  - `POST /hitl/requests/{id}/approve`
  - `POST /hitl/requests/{id}/resume`（执行真正的 tools/call，并把结果写回该 HITL request）
